# Phresto Developer Documentation

> **v2 baseline** — This version removes HTML templating, language/localisation, the Admin/Explorer UI, and the custom per-endpoint discovery format. The framework now emits JSON by default (YAML only for the OpenAPI spec), and exposes a cached OpenAPI 3.0 specification at `/openapi`.

This documentation is written for contributors and advanced users who need to understand how Phresto works internally. For end-user usage see [`docs/sdk/`](../sdk/).

## What Phresto is

Phresto is a small PHP framework for building REST APIs. It is built around these ideas:

- **Convention over configuration** — URL segments map to PHP class and method names.
- **Reflection-based routing** — `Router` inspects controllers and models to decide which method to run and how to bind parameters.
- **Active-record style models** — Models declare fields, relations, and indexes; `MySQLModel` turns that metadata into SQL.
- **Module autoloading** — `Utils` builds a registry of module files so Composer can find project-specific classes under `Phresto\Modules\...`.
- **OpenAPI-driven discovery** — `OpenApi` reflects the whole module tree and writes a cached `config/openapi.json` spec.

## Quick orientation

```
src/
  Router.php          # Entry-point routing
  Controller.php      # Base controller, parameter binding, auth context
  ModelController.php   # REST CRUD for models + related-model escalation
  CustomModelController.php # User extension point for model controllers
  Model.php           # Base model with metadata helpers
  MySQLModel.php      # MySQL persistence for Model subclasses
  Response.php        # JSON/YAML response builders
  OpenApi.php         # OpenAPI 3.0 spec generator and cache
  Utils.php           # Module registry and autoloader
  Config.php          # INI file loader
  Container.php       # Reflection factory
  MySQLConnector.php  # MySQL connection wrapper
  Interf/             # Middleware and RequestContext interfaces
  Auth/               # AuthContext, JWT, revocation cache, client fingerprint
  RequestContext.php  # Default RequestContext implementation (public properties, withAuthContext, withRoute)
template/
  bootstrap.php       # Web entry point (always returns JSON now)
  .htaccess           # Rewrite rules and security blocks
  modules/            # Built-in modules (user is the only one left)
  scripts/            # Migration and model generators
  config/             # INI and cached openapi.json
  migration/          # Initial user setup migration
```

## What changed in v2

- Removed `src/View.php` and all HTML templates, language files, Bower config, and Foundation/AngularJS assets.
- Removed the `admin` and `explorer` modules, plus the `user` module's OAuth/social classes and views.
- Replaced per-controller `discover_get()` JSON with a single cached OpenAPI 3.0 spec generated by `src/OpenApi.php`.
- Added `GET /openapi` (JSON) and `GET /openapi?format=yaml` for YAML output.
- All non-discovery responses are JSON; `Response::json()` is the canonical way to return data.
- Removed the `lusitanian/oauth` dependency.
- Requires **PHP 8.0 or newer**. Removed PHP 7.x compatibility code (e.g. `ReflectionParameter::export()`) and fixed PHP 8 deprecations.
- Added `declare(strict_types=1)` to every PHP file and adopted **PSR-12** code style via [PHP-CS-Fixer](https://github.com/PHP-CS-Fixer/PHP-CS-Fixer).
- Replaced database-stored session tokens with **stateless JWTs**. The DB now only keeps a revocation blacklist, with a file cache in front.
- Moved authentication out of `Controller` and `user` model into a `Middleware` interface and a `RequestContext` that wraps an `AuthContext`. Middleware can be registered globally on `Router` or declared per controller/model.

## PHP 8 and code style

Phresto now requires PHP 8.0+. All source and template files use `declare(strict_types=1)` and follow PSR-12.

PHP-CS-Fixer is provided as a dev dependency. Use the Composer scripts to check or fix style:

```bash
composer cs-check   # dry-run with diff
composer cs-fix     # apply fixes
```

The configuration is in `.php-cs-fixer.php`. It extends PSR-12 with short array syntax, ordered imports, trailing commas in multi-line lists, and the `strict_types` declaration.
